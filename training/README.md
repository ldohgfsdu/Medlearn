# MedLearn Training Workspace

All local model-training assets live under `F:\ml`.

## Layout

- `sft_train.jsonl`: quality-gated training data generated by `scripts/build_sft_dataset.py`
- `sft_smoke_eval.jsonl`: frozen smoke evaluation samples
- `rejected_samples.jsonl`: rejected extraction samples and reasons
- `datasets/`: deterministic train/validation splits
- `checkpoints/`: LoRA checkpoints
- `exports/`: merged or deployable model artifacts
- `reports/`: training and evaluation metrics

Large generated files, checkpoints, and model weights are intentionally ignored by Git.

## Local Runtime

- Training Python: `F:\ml\.venv-sft`
- Ollama executable: `F:\Ollama\ollama.exe`
- Ollama models: `F:\ml\.ollama\models`
- Hugging Face models: `F:\ml\.models\huggingface`
- Qwen3-0.6B (active LoRA base): `F:\ml\.models\modelscope\Qwen\Qwen3-0___6B`
- Qwen3-8B (large model): `F:\ml\.models\huggingface\Qwen\Qwen3-8B`

Current promoted dataset version is recorded in `state/training_dataset.yaml`.
Historical SFT versions live under `training/data/archive/`.
E-drive legacy JSONL copies are preserved in `training/archive/e-ml-train/`.

Do not add machine-specific `G:\ml` paths to scripts or maintained documentation.

## Commands

```powershell
.\.venv-sft\Scripts\python.exe scripts\build_sft_dataset.py
.\.venv-sft\Scripts\python.exe scripts\check_local_ml_layout.py
.\.venv-sft\Scripts\python.exe scripts\train_sft_lora.py `
  --model F:\ml\.models\modelscope\Qwen\Qwen3-0___6B `
  --epochs 3 `
  --max-length 1536
.\.venv-sft\Scripts\python.exe scripts\evaluate_sft_adapter.py `
  --base-model F:\ml\.models\modelscope\Qwen\Qwen3-0___6B `
  --adapter F:\ml\training\checkpoints\qwen3-0.6b-medlearn-lora\final
```

production medical model. It learned the JSON envelope, but held-out evidence
grounding and multi-node recall remain below the release threshold.
