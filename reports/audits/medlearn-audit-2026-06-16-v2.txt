5. 测试缺口

最小修复方案

方案 A（最小，仅 UI，约 10 行）

在 KnowledgeTab 渲染前增加守卫：

function hasEvidence(node: DiseaseKnowledgeNode): boolean {
  const s = node.source_span
  const items = s?.evidence_items?.filter((x) => x.trim()) ?? []
  return items.length > 0 || Boolean(s?.evidence?.trim())
}
// 展开时：!hasEvidence(node) → 显示「证据待核对，要点暂不展示」占位，不渲染 knowledgeNodeText

新增 tests/disease-knowledge.test.js 用例：source_span 为空时不应暴露 content 字符串（可测纯函数提取）。

H4（原 High → Medium）causal_chains API 层可读到未校验链

分类： 真实缺陷（纵深防御不足）；影响取决于生产数据

严重级别理由： UI 已正确拦截（L193–197）；用户正常使用看不到推导答案。风险在 authenticated 客户端可拿到完整 JSON（React Query 缓存 / 网络面板）。若无 pending/review_required 且含 steps.correct_option_id 的行，则为潜伏风险而非已验证泄露。

可复现证据

1. Hook 主动查询 pending/review_required 且 select('*')

supabase.from('causal_chains').select('*')
  .eq('disease_id', diseaseId)
  .in('validation_status', ['valid', 'pending', 'review_required'])

2. 返回对象优先 valid，否则回退第一条（含 pending）

chain: (chainsResult.data ?? []).find((c) => c.validation_status === 'valid')
  ?? chainsResult.data?.[0] ?? null,

3. RLS 不区分 validation_status

CREATE POLICY "causal_chains_select" ON causal_chains
    FOR SELECT USING (auth.role() = 'authenticated');

4. UI 层已拦截（用户面向安全）

if (!chain || chain.validation_status === 'pending' || chain.validation_status === 'review_required') {
  return <Empty ... title="推导训练暂未开放" />
}
if (chain.validation_status !== 'valid' || steps.length < 4 || steps.length > 8) {
  return <Empty ... title="推导链未通过质量门槛" />
}
