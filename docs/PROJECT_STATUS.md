# Medlearn 项目状态

更新时间：2026-06-11

## 结论

代码库已从“多功能医学学习平台”收敛为“病例训练 MVP”。核心工程链路基本可运行，但尚不满足 Alpha 发布门槛。当前最大阻塞不是前端功能，而是病例内容、医学审核、服务端部署和真机端到端验收。

## 已完成

### 工程基础

- 升级并校准 Expo SDK 56 依赖矩阵。
- 建立统一的 TypeScript、ESLint、Node 测试和 Python 测试命令。
- 清理缓存、日志、截图、字节码和失效脚本等无效产物。
- 补充 `.gitignore`，避免模型、缓存、密钥和本地环境进入版本库。

### 安全

- AI 与 Embedding 请求改由 Supabase Edge Functions 代理。
- 客户端公开环境变量中移除服务端密钥。
- 病例标准答案和评分规则改为服务端专用字段。
- 新增列级权限、会话字段保护与医学审核记录约束，客户端不能写最终分数或伪造完成状态。
- 未识别的患者问题改由专用 `case-patient` 函数处理，包含提示注入、诊断泄漏、危险建议和单病例成本上限。

### 病例闭环

- 支持病例启动、问诊、查体、检查、诊断、治疗、评分和反馈。
- 评分改为服务端确定性算法，并支持同义词、鉴别诊断、证据覆盖、危险治疗扣分。
- 治疗权重按病例关键措施数量动态分配。
- 已记录启动、消息、检查、诊断提交、完成和反馈等关键事件。
- 已补齐受限提示、主动结束病例和评分申诉入口。
- 首页与底部导航已收敛到病例训练、病例记录和个人中心。

## 尚未完成

### Alpha 阻塞项

1. **病例库不足**：PRD 要求 15 个已批准病例，当前仓库只有 1 个种子病例，且没有医学审核签字记录。
2. **医学审核未完成**：工程代码不会自动把病例标为 `approved`。
3. **服务端未部署验证**：需要应用迁移 `016_secure_case_scoring.sql`、`017_case_review_workflow.sql` 并部署 `case-submit`。
4. **部署凭据缺失**：当前环境没有 Supabase Access Token 或数据库密码，不能自动应用迁移和部署函数。
5. **远端数据库未初始化**：当前 `.env` 指向的项目中不存在 `case_templates`。
6. **端到端验收缺失**：仍需在 iOS、Android 和真实 Supabase 项目完成整条病例流程。

### 次要项

- 成本单价需要按实际模型供应商配置，否则只能统计 token，成本值为 0。
- 旧的费曼、知识地图、考试和独立 AI 问答代码仍保留，但已从 MVP 默认导航隐藏。
- 历史文档仍有“大而全平台”描述，应以 `docs/MVP_PRD.md` 和本文为当前依据。

## 下一步计划

1. 在测试 Supabase 项目执行全部迁移，部署五个 Edge Functions，验证权限、幂等提交与成本事件。
2. 建立病例 JSON Schema、医学审核清单和 reviewer sign-off 字段。
3. 由医学审核者完成 15 个病例内容；审核通过后再标记为 `approved`。
4. 配置实际模型单价和 Alpha 用户配额，观察单病例成本分布。
5. 在 iOS/Android 完成端到端回归，再决定是否删除已隐藏的非 MVP 模块。

## 发布门槛

进入 Alpha 前至少需要：

- 15 个医学审核通过的病例
- 0 个已知 P0 问题
- 所有病例通过诊断泄漏回归测试
- iOS 与 Android 均可完成首个病例
- 评分结果可复现
- 成本统计生效
