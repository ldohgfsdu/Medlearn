## 1. 概述

### 1.1 产品愿景

**MedLearn** 是一款 AI 驱动的医学思维训练微信小程序，帮助医学生和规培医生通过**费曼学习法**和 **VINDICATE 鉴别诊断框架**建立系统化临床思维，而非死记硬背。

### 1.2 核心价值主张

> **教用户"怎么想"，不是"记什么"。**

市面上医学学习产品（医考帮、百通医学、丁香园题库）本质都是题库 + 视频课程，训练的是"记住答案"的能力。MedLearn 的差异化在于：

| 竞品方式 | MedLearn 方式 |
|----------|---------------|
| 看视频 → 背知识点 → 刷题 | 复述知识点 → AI 评估 → 发现思维盲区 → 针对性补强 |
| 鉴别诊断靠背口诀 | VINDICATE 九维度系统分析，训练临床推理结构 |
| 错题只看解析 | 错题关联知识点 → 费曼复述 → 从根源消除薄弱点 |
| 被动接收 | 主动输出 + AI 即时反馈 |

### 1.3 产品定位

- **不是**题库产品（不做"刷题通过考试"）
- **不是**视频课程（不做"看讲座学知识"）
- **是** AI 驱动的思维训练工具（做"训练临床推理能力"）

### 1.4 技术栈概览

| 层 | 技术 |
|----|------|
| 前端框架 | Taro 4 + React 18 + TypeScript |
| 运行平台 | 微信小程序（基础库 ≥ 2.11.0，微信版本 ≥ 7.0.0） |
| 后端 | 微信云开发（云数据库 + 云函数） |
| AI | 大语言模型（Anthropic Claude / OpenAI 兼容接口） |
| 构建 | Webpack5 → `dist/`，主包 < 2MB |

## 2. 问题陈述

### 2.1 行业痛点

1. **医学教育重知识轻思维**：传统医学教育以知识灌输为主，临床推理能力训练严重不足。医学生能背出疾病特征，却无法系统化地完成鉴别诊断。
2. **AI 医学产品同质化**：现有 AI 医学产品聚焦"问答"和"知识检索"，缺少结构化思维训练框架。
3. **规培医生继续教育缺位**：住院医师规范化培训期间，缺乏碎片化、可量化的思维训练工具。

### 2.2 用户痛点

| 痛点 | 严重程度 | 现有解决方案 | 方案缺陷 |
|------|----------|-------------|----------|
| 鉴别诊断思路混乱，无法系统化 | 🔴 高 | 背口诀、看教材 | 口诀无推理过程，教材不提供反馈 |
| 知识点学了就忘，缺乏间隔重复 | 🔴 高 | 笔记本、Anki | Anki 无医学专业内容，自制卡片成本高 |
| 不知道自己哪里不会（Dunning-Kruger 效应） | 🔴 高 | 做题自测 | 做题只能发现"答错了"，无法定位"思维哪里错了" |
| 碎片时间无法有效利用 | 🟡 中 | 刷短视频 | 无学习效果 |
| 临床思维缺乏实战训练 | 🟡 中 | 见习/实习 | 机会有限，无即时反馈 |

### 2.3 竞品不足

| 竞品 | 核心功能 | 关键不足 |
|------|----------|----------|
| 医考帮 | 题库 + 解析 | 纯刷题，无思维训练 |
| 百通医学 | 视频课程 | 被动学习，无个性化反馈 |
| 丁香园 | 社区 + 病例讨论 | 内容质量参差，无结构化训练 |
| Anki | 间隔重复卡片 | 无医学专业内容，无 AI 评估 |
| ChatGPT / 通用 AI | 自由对话 | 无医学框架引导，幻觉风险高 |

## 3. 目标与目的

### 3.1 北极星指标

**每周完成费曼复述的知识点数量**

选择理由：
- 直接衡量核心价值（主动输出 + AI 反馈）
- 可量化、可追踪、可分解
- 与留存率高度相关（复述越多 = 学习习惯越强 = 留存越高）
- 区别于题库产品的"刷题量"指标

### 3.2 业务目标

| 目标 | 量化指标 | 优先级 |
|------|----------|--------|
| V1.0 上线验证 | 上线 30 天内 DAU ≥ 500 | P0 |
| 核心循环验证 | 上线 60 天内，周费曼复述完成率 ≥ 40%（活跃用户中） | P0 |
| 留存验证 | 次日留存 ≥ 35%，7 日留存 ≥ 15% | P0 |
| 口碑传播 | 上线 90 天内，自然新增占比 ≥ 30% | P1 |
| 付费验证 | V2.0 探索付费模型，付费转化率 ≥ 5% | P2 |

### 3.3 产品目标

| 目标 | 量化指标 | 优先级 |
|------|----------|--------|
| 费曼复述体验闭环 | 从进入知识点到完成复述 ≤ 3 次点击 | P0 |
| AI 响应感知优化 | 用户等待 AI 响应时，3 秒内展示渐进式内容 | P1 |
| 语音输入可用 | 语音识别准确率 ≥ 85%（医学专业术语） | P1 |
| 学习闭环打通 | 错题 → 费曼复述引导率 ≥ 60% | P1 |
| 知识地图可用性 | 用户从知识地图找到目标知识点 ≤ 2 次交互 | P0 |

## 5. 用户故事与使用场景

### 5.1 核心用户故事

**作为一个医学生，我想要用费曼复述的方式检验自己对知识点的理解，并获得 AI 即时反馈，这样我就能发现自己不知道自己不知道的东西。**

### 5.2 场景 1：午休费曼复述（小林）

**背景**：小林刚上完呼吸系统课程，午休有 20 分钟。

1. 打开 MedLearn，首页显示"今日待复习：3 个知识点"
2. 点击"肺炎"知识点，进入费曼复述模式
3. 看到 AI 提示："请用自己的语言解释肺炎的病理机制和临床表现"
4. 小林用语音输入复述（约 2 分钟）
5. AI 3 秒内展示评估框架："准确性 ✅ | 完整性 ⚠️ | 清晰度 ✅ | 深度 ⚠️"
6. 逐维度展开反馈：
   - 完整性：遗漏了"非典型病原体肺炎"的鉴别要点
   - 深度：病理机制描述停留在表面，未涉及免疫应答过程
7. 小林点击"继续对话"，AI 用苏格拉底式提问引导深入
8. 5 分钟后完成，AI 评分从 55 分提升到 72 分
9. 系统自动记录本次学习，更新间隔重复计划

### 5.3 场景 2：值班间隙 VINDICATE 练习（小王）

**背景**：小王值班间隙有 15 分钟，明天查房要汇报一个胸腔积液病例。

1. 打开 MedLearn → 病例沙盒，选择"胸腔积液"相关病例
2. 进入 VINDICATE 鉴别诊断模式
3. 逐类别填写分析：
   - V（血管性）：肺栓塞导致胸腔积液 ✅
   - I（感染性）：结核性胸膜炎 ✅
   - N（肿瘤性）：肺癌胸膜转移 ✅
   - D（退行性）：未填写 ⚠️
   - I（中毒性）：药物性胸腔积液（如胺碘酮）✅
   - C（先天性）：未填写 ⚠️
   - A（自身免疫）：系统性红斑狼疮 ✅
   - T（创伤性）：血胸 ✅
   - E（内分泌）：甲状腺功能减退致胸腔积液 ✅
4. AI 评估：7/9 类别覆盖，遗漏 D（退行性：如心衰导致的漏出液）和 C（先天性：如先天性乳糜胸）
5. 小王补充后，AI 确认覆盖完整，给出每个类别的临床权重排序
6. 第二天查房汇报，鉴别诊断思路清晰，上级医师认可

### 5.4 场景 3：考研复习闭环（小陈）

**背景**：小陈晚上 3 小时复习时间，需要系统化复习消化系统。

1. 打开 MedLearn → 知识地图，切换到"消化系统"
2. 看到系统级进度：35/48 知识点已学习，掌握度分布图
3. 点击"溃疡性结肠炎"，进入费曼复述
4. 复述后 AI 评分 48 分，提示"与克罗恩病的鉴别要点混淆"
5. 系统自动推荐"溃疡性结肠炎 vs 克罗恩病"对比模式
6. 进入对比模式，AI 生成多维度对比表（发病部位、病理特征、临床表现、治疗策略）
7. 小陈逐维度确认理解，标记 2 个仍不清晰的维度
8. 返回知识地图，系统已更新掌握度
9. 打开模拟考试，选择"消化系统"专项，5 道题
10. 答完 3 道错 2 道，系统引导错题关联知识点进行费曼复述
11. 完成闭环：考试 → 诊断薄弱点 → 深度学习 → 下次考试验证

#### F-P0-01：知识地图（三明治结构）

**描述**：用户访问最频繁的页面，采用三明治结构展示 800+ 知识点层级。

**RICE 评分**：Reach=8000 | Impact=3x (Massive) | Confidence=100% | Effort=M (3人月) → **Score=8000**

**详细设计**：

```
🔍 搜索框（固定顶部，支持知识点名称/拼音/ICD编码搜索）

L1 → 8 大系统卡片网格（2行×4列）
      🫀循环系统  🫁呼吸系统  🧠神经系统  🦴运动系统
      🍽️消化系统  💊内分泌系统  🩸血液系统  🫘泌尿系统
      用器官 emoji + CSS 进度环，不用图片

📌 最近学习（动态 3 条，显示知识点名 + 上次评分 + 间隔重复状态）

L2 → 章节折叠面板（手风琴，每次只展开一个）
      右侧 5 段式迷你进度条

L3 → 知识点列表（默认折叠，展开章节时显示）
      每行右侧 5 圆点掌握度 + 待复习铃铛 🔔
```

**交互规则**：
- 点击知识点 → 默认进入**费曼复述模式**（不是详情页），因为北极星指标是"每周完成费曼复述的知识点数量"
- 长按知识点 → 进入详情页（查看内容、关联推导链、历史记录）
- 搜索结果直接展示知识点列表，点击同样进入费曼复述模式

**备选模式**：课程大纲时间线模式（按医学院教学周排列，给按部就班型用户），通过顶部 Tab 切换。

**验收标准**：
- [ ] 8 大系统卡片正确展示，每个卡片显示 emoji + 系统名 + 进度环
- [ ] 手风琴展开/收起动画流畅（≤ 300ms）
- [ ] 搜索框输入后 500ms 内返回匹配结果
- [ ] 最近学习 3 条动态更新，展示上次 AI 评分
- [ ] 知识点列表 5 圆点掌握度与间隔重复数据同步
- [ ] 待复习铃铛仅在间隔重复到期时显示
- [ ] 课程大纲时间线模式可切换，按教学周排列
- [ ] 主包体积增量 ≤ 50KB（纯 emoji + CSS，无图片资源）
- [ ] CI 构建后主包体积 ≤ 1.8MB，超限构建失败（`scripts/check-size.sh`）

#### F-P0-02：费曼复述模式

**描述**：核心功能。用户用自己的语言复述知识点，AI 评估准确性/完整性/清晰度/深度。

**RICE 评分**：Reach=8000 | Impact=3x (Massive) | Confidence=100% | Effort=M (3人月) → **Score=8000**

**详细设计**：

1. **进入方式**：从知识地图点击知识点 → 直接进入费曼复述模式
2. **AI 提示**：展示知识点标题 + "请用自己的语言解释..."提示语
3. **输入方式**：
   - 文本输入（基础）
   - 语音输入（P1，见 F-P1-02）
4. **AI 评估**（渐进式展示）：
   - 0-3 秒：展示评估框架骨架（四维度图标 + 加载动画）
   - 3-8 秒：逐维度填充评分和简要反馈
   - 8 秒+：完整反馈内容展示
5. **评估维度**：
   - 准确性（0-100）：事实是否正确
   - 完整性（0-100）：是否覆盖关键要点
   - 清晰度（0-100）：表达是否条理清晰
   - 深度（0-100）：是否涉及机制层面
6. **后续动作**：
   - "继续对话"：进入苏格拉底式对话（F-P0-03）
   - "查看要点"：展示知识点关键要点对比
   - "下次再来"：返回知识地图

**验收标准**：
- [ ] 从知识地图点击知识点到进入复述模式 ≤ 1 次点击
- [ ] AI 评估 3 秒内展示框架骨架，用户不再面对空白等待
- [ ] AI 响应超过 15 秒 → 展示"🤔 AI 正在深度分析中，请稍候…"提示 + "取消"按钮（返回输入态）
- [ ] AI 响应超时（> 30 秒）→ 展示错误提示"分析超时，请检查网络后重试" + "重新提交"按钮
- [ ] 用户点击"取消"后，已输入内容保留在输入框中，不丢失
- [ ] 四维度评分均为 0-100 整数
- [ ] 评估结果自动保存至 `feynman_records` 集合
- [ ] 评分更新间隔重复计划（F-P0-06）
- [ ] 所有 AI 输出固定展示"⚠️ AI 生成内容，不构成医学建议"标识

#### F-P0-03：苏格拉底式对话

**描述**：AI 不直接给答案，而是通过提问引导用户深入思考。

**RICE 评分**：Reach=6000 | Impact=2x (High) | Confidence=100% | Effort=S (1.5人月) → **Score=8000**

**详细设计**：

1. **触发方式**：费曼复述完成后点击"继续对话"
2. **对话模式**：AI 根据复述中的薄弱点提出引导性问题

### 6.5.1 优先级调整说明

以下功能的最终优先级不完全由 RICE Score 决定，调整原因如下：

| 功能 | RICE | 最终 | 调整原因 |
|------|------|------|----------|

| F-P1-01 模拟考试 | 2,667 | P1 | RICE 略高于病例沙盒，但模拟考试与竞品的差异化程度低于病例沙盒。V1.0 核心任务是验证"费曼复述 + VINDICATE"闭环，模拟考试的"考试→费曼→验证"闭环依赖费曼复述先稳定，放在 V1.5 更合理 |

**原则**：RICE 是排序参考，不是最终决策。当以下情况出现时可调整：
1. 功能之间存在强依赖关系（被依赖者优先）
2. Impact 评估有结构性偏差（如低估了整合型功能的价值）
3. 战略优先级（差异化程度）高于 RICE 数值

| Prompt 越长 token 消耗越大 | 中 | 成本超预算 | 教材原文按需引用（仅引用相关段落，非全章） |

> **说明**：当前 V1.0 采用用户自带 API Key 模式，上述成本由用户自行承担。V1.5 探索平台提供免费额度的可行性。上述估算用于团队理解 AI 使用量级，非平台直接成本。
